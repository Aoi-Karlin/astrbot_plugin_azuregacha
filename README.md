# Azure 收藏集抽卡

把 Bilibili「收藏集」做成抽卡玩法：按官方流通量算出的概率抽卡，收集进度全局累计，抽卡消耗的积分直接读写打卡插件的余额。

移植自 Koishi 版抽卡插件，去掉了打工/蹭饭那套额外赚分玩法，只保留抽卡。

## 依赖与渲染

- [astrbot_plugin_azuresignin](https://github.com/)（积分来源，必须同时安装）
- `playwright` + `jinja2`（见 `requirements.txt`）
- AstrBot >= 4.13.0

结果图和图鉴由插件自己用 Playwright 驱动无头 Chromium 渲染，不走 AstrBot 的 t2i，也不依赖 Pillow。首次安装要装一次浏览器：

```bash
pip install playwright
playwright install chromium
```

因为渲染在本机进程内完成，模板直接用 `file://` 引用卡图和角标，不再把图转成 base64——省掉了缩略图缓存，`cache/` 目录现在只放渲染出来的成品。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/抽卡 [1-10]` | 抽卡，每抽 10 积分。先出一张结果图，再逐张发卡图 |
| `/卡池` | 列出 24 个奖池和收集进度，`▸` 标出当前奖池 |
| `/换池 序号` | 切换本群奖池；`/换池 全部卡池` 抽全部；也支持写池名或系列名 |
| `/图鉴` | 按系列生成本人图鉴，未收集的卡显示为灰色；每页最多 36 张，超了自动分页 |
| `/获取卡 卡名` | 发送已拥有卡的原图 |
| `/抽卡帮助` | 帮助 |
| `/发积分 数量 [@某人]` | **管理员**：增减积分，负数即扣除 |
| `/发卡 卡名 [数量] [@某人]` | **管理员**：直接发卡，不消耗积分、不掷概率 |

管理员指令走 `PermissionType.ADMIN`，只有 AstrBot 管理员能用；不写 `@某人` 就发给自己。`/发卡` 的数量可以写 `×3` 或空格加数字。

## 图鉴

图鉴和打卡卡面是同一套视觉：Noto Sans SC + LiquidGlass 液态玻璃，画布 1800px 宽、6 列网格，卡面按 2 倍尺寸生成，发到群里不糊。

- **左上角角标**：大隐藏 / 小隐藏使用官方 `tag_40` / `tag_30` 素材
- **底部居中**：镭射款标记
- 未收集的卡整体压成灰度；右上角是持有数量

## 镭射款

`洛天依·新像集`（act `113552`）的**普通卡**在抽到时另有 **15%** 概率变成「镭射款」。镭射款是同一张卡的变体，单独计数，图鉴和抽卡结果图底部都会盖上镭射款标记。

素材是 `assets/laser.png`，想换标直接替换这个文件即可（建议保持同样的横向胶囊比例）。

## 奖池模式

- **全部卡池**：先按卡池大小加权选池，再按池内官方概率抽卡，稀有 / 小隐藏 / 大隐藏额外乘 0.4 压缩系数。
- **系列**：例如 `/换池 洛天依·收藏集`，在该系列的 6 个池之间抽。
- **单池**：例如 `/换池 纯蓝幻乐`，只在池内按官方概率抽。

收集进度按人全局累计，换群不会丢；奖池选择按群记，各群互不干扰。

## 素材准备

卡图和目录不打进插件包，放在 AstrBot 数据目录里：

```
<astrbot>/data/plugin_data/astrbot_plugin_azuregacha/
├── catalog.json          # 卡目录（只保留有图的卡）
└── cards/<hash>.jpg      # 1080px 宽 JPEG
```

用 `tools/prepare_cards.py` 从原始素材生成：

```bash
python tools/prepare_cards.py \
  --source "D:\BiliDLC" \
  --catalog path/to/catalog.json \
  --out "<astrbot>/data/plugin_data/astrbot_plugin_azuregacha"
```

脚本按「卡名 + 档位」把中文文件名的原图对到目录里的哈希，转成 1080px、质量 88 的 JPEG，并把过滤后的目录一起写出来。

当前素材覆盖 **213 / 423** 张卡（限时卡未下载），没有图的卡不会进卡池，也不会出现在图鉴里。想补齐就补图后重跑脚本。

图鉴底图默认用 `assets/default_bg.jpg`；想换自己的一版，往数据目录里丢一张 `background.jpg` 就会自动顶替（会自动缩到 1800px 宽，并按顶部亮度决定玻璃厚度）。

## 关于积分

积分不单独存，直接走打卡插件的键值：

- 读：`sp.get_async("plugin", "azure/astrbot_plugin_azuresignin", "user_<uid>", {})` 的 `points`
- 写：同上，改完 `points` 再写回，其他字段（连续天数、最佳纪录等）原样保留

所以打卡和抽卡共用一个余额，积分不够就发 `/打卡`——这是这个玩法闭环的关键。如果打卡插件没装，抽卡会一直提示积分不足。
